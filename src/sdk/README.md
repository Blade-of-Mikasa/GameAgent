# SDK 状态管理

`StateStore` 为一个 SDK 会话保存当前观测及局面版本，使用已有的 `Observation` 契约。

- `update(observation)`：接受更新返回 `true`；序号重复或倒退返回 `false`，状态保持不变。
- `getState()`：返回包含 `observation` 和 `stateVersion` 的独立副本；首次观测前返回 `null`。

## 版本与顺序

本局首次观测的版本为 1。之后仅比较 `snapshot`，内容变化时版本加 1；
内容不变时保留版本，但仍保存最新观测的 ID、序号和时间。
对象属性的书写顺序不参与比较；玩家和手牌的数组顺序保留并参与比较。

观测顺序只由 `sequence` 决定，不依赖观测时间。序号必须是安全整数，可以跳号，
但换局时也必须继续递增。新对局使用新的 `gameId`，其局面版本从 1 开始。
序号检查先于换局处理，因此低序号的旧局观测不能覆盖新局状态。

读写均复制数据，调用方修改输入对象或读取结果不会污染内部状态。
本模块接收符合契约的完整观测，仅额外检查序号；适配器的数据解析和其他合法性检查不在此处实现。
它只保存当前状态，不保存历史，也不创建决策请求或执行动作。

## 验证

使用 Node.js 24 或更新版本，在仓库根目录运行：

```sh
npm ci
npm run typecheck
npm test
```

测试使用 Node 自带的测试工具，覆盖版本递增、重复与乱序观测、换局及对象修改隔离。
